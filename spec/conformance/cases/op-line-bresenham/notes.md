# op-line-bresenham

- 形态:**仅渲染正例**(`op-` / `blend-` 前缀,§13.1 / README §2.1b)
- 输入:`input.pxl`(手写;**没有** `input.png`,也没有「抽取零 diff」判据)
- 尺寸:16x16
- `expected.pixels.sha256`:`e37e7dea4f4eb68fad94a53abea88237555bcfe428aa19441ab2258f500c9d7b`

## 覆盖条款

`§5.4`(逐字符固定的 Bresenham,含两端点)、`§5.4`(两个 `若` 各自独立判断,同一轮可能同时走 x 与 y)、`§5.4`(**不做端点交换归一**:`line(a,b)` 与 `line(b,a)` 的像素集可以不同)、`§5.4`(退化单点、水平线无锯齿)、`§5.0`(逐点裁剪)。

## 期望值来源

八条从 `(7,7)` 出发的单向线覆盖八个八分圆方向;第 9、10 条是**同一对端点按相反方向**画出的两条线(正向 slot 1、反向 slot 2),用来钉住 §5.4 明确禁止的「交换端点归一」。按本文件 oracle 的逐点计算:

```
正向 (2,6)->(10,5) 共 9 点:[(2, 6), (3, 6), (4, 6), (5, 6), (6, 5), (7, 5), (8, 5), (9, 5), (10, 5)]
反向 (10,5)->(2,6) 共 9 点:[(10, 5), (9, 5), (8, 5), (7, 5), (6, 6), (5, 6), (4, 6), (3, 6), (2, 6)]
只在正向出现:[(6, 5)]
只在反向出现:[(6, 6)]
```

两者点数相同(9 = 9)但点集不同,所以把两条都画出来之后,两个方向的差异各自留下自己的 slot 颜色。第 11 条是退化单点(`x0==x1 && y0==y1`),第 12 条是水平线(y 恒 12,无锯齿偏移)。

## 判据

§13.2b 的五条同时成立:

1. **回渲像素一致**:渲染器读 `input.pxl`,产出的 RGBA8 字节流 SHA-256 等于
   `expected.pixels.sha256`;
2. **确定性**:同一文档两跑,PNG **文件**逐字节相同(§9);
3. **不拘形式**:该文档本就不是规范抽取器能产出的形态(含 `pixel` / `line` /
   `mirror` / `erase` / `stamp` 之一,或含非 `normal` 的 `blend`),渲染器必须照样接受(§3.8);
4. **尺寸一致**:输出 PNG 的宽高等于 `input.pxl` 声明的值(摘要不含尺寸,必须单独断言);
5. **输出结构合规**:8 bit / 色彩类型 6 / 非交错 / 所有行过滤器字节恒 0 /
   chunk 类型序列 `IHDR` → `IDAT`⁺ → `IEND`(§10)。

## 摘要怎么来的

`expected.pixels.sha256` 由 `spec/conformance/tools/pxl_render_ref.py` —— **按规范另写**的
渲染 oracle(不 import `importer`、不 import `tests/`)—— 对 `input.pxl` 渲染后
按 §13.4 的字节流定义(逐行、行内自左向右、自上而下,每像素 R,G,B,A,无填充)
计算,并经被测实现之外的第二条路径复核。生成命令:

```

```
