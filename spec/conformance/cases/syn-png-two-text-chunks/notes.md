# syn-png-two-text-chunks

- 尺寸:16x16
- PNG:色彩类型 6(RGBA)+ 两条 `tEXt`(关键词 `Comment` 与 `Software`,不参与像素)、8 bit、非交错、行过滤器恒 0
- 非透明色数(n):2

## 覆盖条款

`§8.5`(重复约束按"该 chunk 是否被读取"分类:ancillary 出现任意次都接受、内容一律忽略)、`§8.1`(ancillary chunk 接受并忽略,不得因其存在而报错)。

## 期望值来源

上半 8 行是 `336699`、下半 8 行是 `CC3300`,均 a = 255 → 2 个互不相同的非透明 texel 值,n = 2;n ≤ 61 → char 档。每行段长 16 → 全部 RUNNER 行,上下两块 slot 不同 → 2 条 `rect`(w = 16,h = 8)。两条 `tEXt` 的关键词不同(`Comment` / `Software`),按 §8.5 都属于"不被读取"的 ancillary,重复出现必须接受、内容一律忽略。


`expected.pixels.sha256` 按 §13.4 计算:逐行、行内自左向右、自上而下,每像素 R,G,B,A 四字节,无填充,共 1024 字节;由本文件持有的**意图像素**直接算出,不经过任何 PNG 解码。

**判据**:本用例的判据是"两条 `tEXt` 必须被接受并忽略",因此它的 `expected.pxl` 必须与**像素完全相同、不带任何 `tEXt` 的版本**逐字节相同——两条关键词不同的 `tEXt` 不得改变抽取结果的任何一个字节。(不带 `tEXt` 的那份不入库,判据靠这条文字表述与抽取器的实现共同保证。)它是 `neg-png-duplicate-chunk`(重复的**被读取** chunk 必须拒绝)的对照。
