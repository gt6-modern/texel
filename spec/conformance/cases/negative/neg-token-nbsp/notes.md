# negative/neg-token-nbsp

- 形态:**负例**(§13.1)
- **受测侧**:渲染侧(目录内只有 `input.pxl`)
- 受测输入:`input.pxl`
- 期望错误码:`PXL001`(见 `expected.error`,一行 + LF)
- 缺陷数量:1(§13.1 / README §2.2 要求一个目录只放一个缺陷)

## 覆盖条款

`§3.4`(行内只允许 §4.2 / §4.3 枚举出的 token 字符;不得用宿主语言的「是否为空白」分类)、`§11.1` 阶段 5。

## 缺陷(只有这一处)

`grid` 行内含一个 U+00A0(非断行空格)。它在很多语言的「空白」分类里是空白,但 §3.4 只认枚举字符集 → 阶段 5 报 `PXL001`。本文件把这个字符写成 JSON 转义 `\u00a0`(§3.8 要求渲染器接受转义):解码后的码点必须真的是 U+00A0,而它不在 §4.2 的枚举字符集里 → 阶段 5 报 `PXL001`。

本目录**没有** `input.png`,`expected.pixels.sha256` 也不存在——负例不产出期望像素,只钉错误码与「不留输出文件」。**没有** `expected.pxl`:负例绝不放它。

## 判据

§13.2c:实现必须以 `PXL001` 失败,且**不产出任何输出文件**(不得留半份)。
