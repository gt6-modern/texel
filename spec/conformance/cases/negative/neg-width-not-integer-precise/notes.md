# negative/neg-width-not-integer-precise

- 形态:**负例**(§13.1)
- **受测侧**:渲染侧(目录内只有 `input.pxl`)
- 受测输入:`input.pxl`
- 期望错误码:`PXL002`(见 `expected.error`,一行 + LF)
- 缺陷数量:1(§13.1 / README §2.2 要求一个目录只放一个缺陷)

## 覆盖条款

`§3.8`(整数性与区间必须按数字的原始词法做精确十进制判断,不得先转二进制浮点)、`§11.1` 阶段 6。

## 缺陷(只有这一处)

`width` 写成 `1.0000000000000001`。它与 1 **不相等**,是 `PXL002`;常见的双精度解析会把它舍成 `1.0` 从而误接受——这正是 §3.8 要钉的分叉点。与 `op-numeric-literal-forms` 成对(那一例的 `2.0` 等值,必须接受)。

本目录**没有** `input.png`,`expected.pixels.sha256` 也不存在——负例不产出期望像素,只钉错误码与「不留输出文件」。**没有** `expected.pxl`:负例绝不放它。

## 判据

§13.2c:实现必须以 `PXL002` 失败,且**不产出任何输出文件**(不得留半份)。
