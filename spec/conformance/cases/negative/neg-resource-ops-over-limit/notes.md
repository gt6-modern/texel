# negative/neg-resource-ops-over-limit

- 形态:**负例**(§13.1)
- **受测侧**:渲染侧(目录内只有 `input.pxl`)
- 受测输入:`input.pxl`
- 期望错误码:`PXL002`(见 `expected.error`,一行 + LF)
- 缺陷数量:1(§13.1 / README §2.2 要求一个目录只放一个缺陷)

## 覆盖条款

`§5.0.2`(每层 `ops` 数上界 32,768)、`§11.1` 阶段 6。

## 缺陷(只有这一处)

单层 32,769 条 `fill slot 0`(每条都是一次合法的透明填充),超过每层 32,768 上限。生成后实测 **2130209 字节**(2.03 MiB),低于 §13.6 的 4 MiB 阈值,因此**必须入库**,不走生成路径。(README §5.1 与该行的 `covers` 记的是 2,130,193 字节,与本文件相差 16 字节——fixture 的构造细节不同,以本处的实测值为准。)

本目录**没有** `input.png`,`expected.pixels.sha256` 也不存在——负例不产出期望像素,只钉错误码与「不留输出文件」。**没有** `expected.pxl`:负例绝不放它。

## 判据

§13.2c:实现必须以 `PXL002` 失败,且**不产出任何输出文件**(不得留半份)。
