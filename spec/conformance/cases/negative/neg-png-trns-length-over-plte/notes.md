# negative/neg-png-trns-length-over-plte

- 形态:**负例**(§13.1)
- **受测侧**:抽取侧(目录内只有 `input.png`,抽取器根本不读 PXL)
- 受测输入:`input.png`
- 期望错误码:`PXL006`(见 `expected.error`,一行 + LF)
- 缺陷数量:1(§13.1 / README §2.2 要求一个目录只放一个缺陷)

## 覆盖条款

`§8.5`(色彩类型 3 的 `tRNS` 长度不得超过 `PLTE` 项数;依赖另一个 chunk 的上界检查以该 chunk 已经出现为前提)。

## 缺陷(只有这一处)

顺序完全合法:`IHDR → PLTE → tRNS → IDAT → IEND`,`PLTE` 只有 4 项(12 字节),`tRNS` 却给了 8 字节——**只有长度这一条**违规。它把「顺序错」与「长度错」分开钉住:两者都报 PXL006,只有拒绝原因能把它们区分开;少了这一条,把顺序错的用例改成长度错也不会有任何门禁变红。

`input.png` 实测 **118 字节**;本目录没有 `input.pxl`,也没有任何期望像素文件。

## 判据

§13.2c:实现必须以 `PXL006` 失败,且**不产出任何输出文件**(不得留半份)。
