# negative/neg-priority-001-over-003-codepoint-length

- 形态:**负例**(§13.1)
- **受测侧**:渲染侧(目录内只有 `input.pxl`)
- 受测输入:`input.pxl`
- 期望错误码:`PXL001`(见 `expected.error`,一行 + LF)
- 缺陷数量:1(§13.1 / README §2.2 要求一个目录只放一个缺陷)

## 覆盖条款

`§3.4`(长度一律按 JSON 解码后的 **Unicode 码点**计数,不按字节、不按 UTF-16 代码单元)、`§11.1` 阶段 3(各行等长)先于阶段 4(`encoding` 取值)。

## 缺陷(只有这一处)

**刻意的阶段序用例**:`grid` 是 `["\uD83D\uDE00", "00"]`,`encoding` 未知。那个转义代理对解码后是**一个**码点,所以两行长度是 1 与 2——不等长,属阶段 3 的 `PXL001`。若按 UTF-16 代码单元计,两行是 2 与 2(等长),就会滑到阶段 4 报 `PXL003`。§3.4 把计数单位写死为码点,就是为了同一份文件不给两个答案。(本文件的字节里,那一行是 `json.dumps` 写出的 `\uD83D\uDE00` 转义;渲染器按 JSON 解码后必须只见到一个码点。)

本目录**没有** `input.png`,`expected.pixels.sha256` 也不存在——负例不产出期望像素,只钉错误码与「不留输出文件」。**没有** `expected.pxl`:负例绝不放它。
