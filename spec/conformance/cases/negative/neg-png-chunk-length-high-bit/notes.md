# negative/neg-png-chunk-length-high-bit

- 形态:**负例**(§13.1)
- **受测侧**:抽取侧(目录内只有 `input.png`,抽取器根本不读 PXL)
- 受测输入:`input.png`
- 期望错误码:`PXL006`(见 `expected.error`,一行 + LF)
- 缺陷数量:1(§13.1 / README §2.2 要求一个目录只放一个缺陷)

## 覆盖条款

`§8.5`(chunk 长度按 32 位无符号读,必须 `len <= 2,147,483,647`,且 `8 + len + 4 <= 文件剩余字节数`)。

## 缺陷(只有这一处)

IHDR 之后紧跟一个长度字段为 `0x80000000` 的 chunk(最高位为 1)。按无符号读是一个荒谬的大长度、按有符号读是负数——两种错法不同,但都必须被同一条规则挡住。

`input.png` 实测 **97 字节**;本目录没有 `input.pxl`,也没有任何期望像素文件。

## 判据

§13.2c:实现必须以 `PXL006` 失败,且**不产出任何输出文件**(不得留半份)。
