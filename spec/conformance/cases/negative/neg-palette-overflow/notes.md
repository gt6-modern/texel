# negative/neg-palette-overflow

- 形态:**负例**(§13.1)
- **受测侧**:抽取侧(目录内只有 `input.png`,抽取器根本不读 PXL)
- 受测输入:`input.png`
- 期望错误码:`PXL005`(见 `expected.error`,一行 + LF)
- 缺陷数量:1(§13.1 / README §2.2 要求一个目录只放一个缺陷)

## 覆盖条款

`§4.5`(`n >= 65536` 无档位可派生)、`§13.1`(抽取侧的 `PXL005`:色数超出该档容量)、`§3.5`(全部像素 alpha = 255,故没有任何 `00000000` 可并入透明 slot)。

## 缺陷(只有这一处)

256×256 共 65536 个像素,每个都是**不同的非透明 RGBA 值**(alpha 恒 255,所以一个透明 slot 也没有)。尺寸 256×256 与面积 65536 都合规,去重后 `n = 65536` 大于 `index4` 容量 65535,只能由抽取器报 `PXL005`——这时**根本没有 PXL 文档可读**,因此本目录只有 `input.png`,没有 `input.pxl`(§13.1 的侧别规则;渲染侧的 `PXL005` 由 `neg-palette-lowercase` 等条目覆盖)。

`input.png` 实测 **209355 字节**;本目录没有 `input.pxl`,也没有任何期望像素文件。

## 判据

§13.2c:实现必须以 `PXL005` 失败,且**不产出任何输出文件**(不得留半份)。
