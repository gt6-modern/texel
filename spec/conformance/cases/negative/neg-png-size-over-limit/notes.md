# negative/neg-png-size-over-limit

- 形态:**负例**(§13.1)
- **受测侧**:抽取侧(目录内只有 `input.png`,抽取器根本不读 PXL)
- 受测输入:`input.png`
- 期望错误码:`PXL006`(见 `expected.error`,一行 + LF)
- 缺陷数量:1(§13.1 / README §2.2 要求一个目录只放一个缺陷)

## 覆盖条款

`§8.3`(`width` / `height` 超过 65536 必须在**输入侧**拒绝)、`§5.0.1`。

## 缺陷(只有这一处)

IHDR 声明 `width = 70000`,`height = 1`。这样的 PNG 无论怎么抽都写不出合法 PXL(画布上界 65536),必须在输入侧拒绝,而不是等抽取完再撞上 `PXL002`。文件本身很小:拒绝发生在读 IHDR 之后,不需要真的解压出 70000 像素。

`input.png` 实测 **67 字节**;本目录没有 `input.pxl`,也没有任何期望像素文件。

## 判据

§13.2c:实现必须以 `PXL006` 失败,且**不产出任何输出文件**(不得留半份)。
