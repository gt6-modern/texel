# negative/neg-palette-over-capacity

- 形态:**负例**(§13.1)
- **受测侧**:渲染侧(目录内只有 `input.pxl`)
- 受测输入:`input.pxl`
- 期望错误码:`PXL005`(见 `expected.error`,一行 + LF)
- 缺陷数量:1(§13.1 / README §2.2 要求一个目录只放一个缺陷)

## 覆盖条款

`§4.5`(`n >= 65536` 时没有可派生的档位,阶段 7 被跳过)、`§11.1` 阶段 9、`§3.2`。

## 缺陷(只有这一处)

`palette` 恰好 65536 项(= `index4` 值域总数,含透明值)。`n >= 65536` 时「声明值是否等于派生值」这句话无从判断,阶段 7 因此**跳过**,直接由阶段 9 报 `PXL005`。若改成 `PXL003`,就会与 `neg-priority-005-over-003-palette-capacity` 打架。fixture 约 1.1 MB,低于 4 MiB 阈值,入库。

本目录**没有** `input.png`,`expected.pixels.sha256` 也不存在——负例不产出期望像素,只钉错误码与「不留输出文件」。**没有** `expected.pxl`:负例绝不放它。

## 判据

§13.2c:实现必须以 `PXL005` 失败,且**不产出任何输出文件**(不得留半份)。
