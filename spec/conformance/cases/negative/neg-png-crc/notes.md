# negative/neg-png-crc

- 形态:**负例**(§13.1)
- **受测侧**:抽取侧(目录内只有 `input.png`,抽取器根本不读 PXL)
- 受测输入:`input.png`
- 期望错误码:`PXL006`(见 `expected.error`,一行 + LF)
- 缺陷数量:1(§13.1 / README §2.2 要求一个目录只放一个缺陷)

## 覆盖条款

`§8.5`(**每一个 chunk 的 CRC 都必须校验**,不逐类型列举)。

## 缺陷(只有这一处)

IDAT 的 CRC 字段被改成 `DEADBEEF`(数据本身仍可解压)。§8.5 要求校验每个 chunk 的 CRC;按「能不能读出像素」放行会让两个实现在这里分叉。IEND 的同类缺陷由 `neg-png-iend-crc` 单独覆盖。

`input.png` 实测 **89 字节**;本目录没有 `input.pxl`,也没有任何期望像素文件。

## 判据

§13.2c:实现必须以 `PXL006` 失败,且**不产出任何输出文件**(不得留半份)。
