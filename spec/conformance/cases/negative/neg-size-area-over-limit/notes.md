# negative/neg-size-area-over-limit

- 形态:**负例**(§13.1)
- **受测侧**:渲染侧(目录内只有 `input.pxl`)
- 受测输入:`input.pxl`
- 期望错误码:`PXL002`(见 `expected.error`,一行 + LF)
- 缺陷数量:1(§13.1 / README §2.2 要求一个目录只放一个缺陷)

## 覆盖条款

`§5.0.2`(`width × height <= 2^22`)、`§11.1` 阶段 6(文档侧面积检查)。

## 缺陷(只有这一处)

`width` = 2049、`height` = 2048,各自都合法,乘积 4,196,352 超过 2^22 = 4,194,304。文档本身极小(每层 `ops` 为空),专测**文档侧**面积上界 —— 它必须与输入侧(`neg-png-area-over-limit`)分开,因为越界报的码不同(`PXL002` vs `PXL006`)。

本目录**没有** `input.png`,`expected.pixels.sha256` 也不存在——负例不产出期望像素,只钉错误码与「不留输出文件」。**没有** `expected.pxl`:负例绝不放它。

## 判据

§13.2c:实现必须以 `PXL002` 失败,且**不产出任何输出文件**(不得留半份)。
