# negative/neg-version-out-of-long-range

- 形态:**负例**(§13.1)
- **受测侧**:渲染侧(目录内只有 `input.pxl`)
- 受测输入:`input.pxl`
- 期望错误码:`PXL001`(见 `expected.error`,一行 + LF)
- 缺陷数量:1(§13.1 / README §2.2 要求一个目录只放一个缺陷)

## 覆盖条款

`§12`(任何非 0 的 `version` 一律 `PXL001`)、`§3.8`(按原始词法精确判定,不经二进制浮点)、`§11.1` 阶段 3。

## 缺陷(只有这一处)

`version` 写成 2^63(`9223372036854775808`):词法是整数,但**超出 64 位可表示范围**。实现若只用「整数值 == 0」判定,会把无法表示的值读成 0 从而**误接受**(解析层用一个「整数但不可表示」的哨兵时尤其容易);正确做法是先判能不能表示,再判值。这条钉住 §12 的 fail-closed。

本目录**没有** `input.png`,`expected.pixels.sha256` 也不存在——负例不产出期望像素,只钉错误码与「不留输出文件」。**没有** `expected.pxl`:负例绝不放它。

## 判据

§13.2c:实现必须以 `PXL001` 失败,且**不产出任何输出文件**(不得留半份)。
