# v1/cases/negative/neg-path-escape-root

- 形态:`negative` 负例(PXL.md §13.3);`defect: path`
- **受测侧**:阶段 R1(§11.2 阶段表第 11 行:每个 asset 声明的逻辑路径语法与规范化)
- 受测输入:`entry.pxl`
- 期望错误码:`PXL008`(见 `expected.error`,一行 + LF)
- 缺陷数量:**1**(声明的 `path` 逃出 asset root)

## 覆盖条款

- §7:`..` 段**允许出现**,但只能参与规范化;逐段处理后 `..` 弹出,弹出时栈已空即
  **字符串层逃逸**。入口在 root,故 `../outside/blade.pxl` 的第一段 `..` 在空栈上弹出 → 逃逸;
- §8.2:resolver 的 `ESCAPE` 映射为 `PXL008`(本用例在**字符串层**就判定,不需要碰宿主文件系统);
- §9.1:**所有** asset 声明都必须通过逻辑路径语法校验,**无论是否被当前 target 选中**;
- §11.2:阶段 R1 排在 v0 全部九阶段之后,所以本条的码不会被 palette/op 等更早阶段抢走。

## 缺陷(只有这一处)

`assets.blade.path = "../outside/blade.pxl"`。字段存在、是字符串、名字合法、`kind` 合法 ——
唯独规范化后在 root 之上。

**这条 asset 没有被任何 `stamp` 选中**(本目录 `ops` 只有 `fill`)。这是刻意的:
它证明 §9.1 的“声明本身全量校验”独立于“只有被选中的才读取”。若实现把路径校验推迟到
“解析被选中的依赖”那一步,本条会**静默通过** —— 而这正是它要抓的错。

## 判定方式

实现必须以 `PXL008` 失败,且不产出任何输出文件。目录里没有 `parts/`:逃逸目标在 root 之外,
按 §13.3.1 不能在用例目录里表达(否则用例自己就越界了)。

## 与 v0 的差异

v0 无外部路径概念,不存在该错误码路径;本条是 v1 新语义的首个 `PXL008` 用法。
