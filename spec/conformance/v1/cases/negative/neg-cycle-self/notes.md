# v1/cases/negative/neg-cycle-self

- 形态:`negative` 负例(PXL.md §13.3);`defect: cycle`
- **受测侧**:阶段 R3(§11.2 第 13 行:循环检测)
- 受测输入:`entry.pxl`
- 期望错误码:`PXL010`(见 `expected.error`,一行 + LF)
- 缺陷数量:**1**(直接自引用)

## 覆盖条款

- §9.2 循环检测身份是**规范化逻辑路径**,**不考虑 bindings**;同一路径再次出现在当前递归栈中
  即为循环;
- §9.2 末句:改变 bindings 不能构造递归(本条没给 bindings,先把“同一路径”这一半钉住);
- §11.2:阶段 R3 排在 R2(解析依赖)之后、R4(会话预算)之前。

## 缺陷(只有这一处)

`assets.again.path = "entry.pxl"` —— 入口引用**它自己**,并用 `stamp` 选用了它。

这条构造有意让 R3 与 R4 相邻:一个自引用文档同时“深度无限”也“文件数无限”。若实现先判预算,
会报 `PXL011`;按 §11.2 的顺序必须先报 `PXL010`。**阶段表的相邻边界由这条钉住。**

## 判定方式

实现必须以 `PXL010` 失败,且不产出任何输出文件。

## 为什么 `expected.error` 里没有引用链

§13.3.4:`expected.error` 内容**恰好**是错误码,说明写 `notes.md`。§9.3 要求的“根入口 +
失败文件 + 完整引用链”是实现侧错误对象与阶段 2 harness 的检查项,不是这个文件的格式。
本阶段不把链条写进 `expected.error`。

## 与 v0 的差异

v0 无外部引用,不可能有循环;v0 的错误码里也没有 `PXL010`。
