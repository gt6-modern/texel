# v1/cases/negative/neg-budget-ref-depth

- 形态:`negative` 负例(PXL.md §13.3);`defect: budget`
- **受测侧**:阶段 R4(§11.2 第 14 行:会话预算,**按表内顺序**判:深度 → 节点数 → 文件数 →
  累计字节 → 累计像素 → 全局光栅)
- 受测输入:`entry.pxl` + `parts/a01.pxl` … `parts/a65.pxl`
- 期望错误码:`PXL011`(见 `expected.error`,一行 + LF)
- 缺陷数量:**1**(引用深度超过 64)

## 目录与引用链

线性链,每一层只有一个外连边:

```text
entry.pxl        -> parts/a01.pxl
parts/a01.pxl    -> a02.pxl          (相对它自己所在目录 parts/)
...
parts/a64.pxl    -> a65.pxl
parts/a65.pxl    叶子:只有一条 fill
```

入口深度 0,所以 `a65` 的深度是 **65** —— 比 §10.2 的“PXL 引用最大深度 **64**”多 1。

## 覆盖条款

- §10.2:`PXL 引用最大深度` 上限 64;
- §11.2 阶段 R4:预算按表内顺序判定,深度**最先**判 —— 本用例刻意让其它预算都远远够用
  (见下),于是唯一可能触发的就是深度;
- §7 相对解析(链的每一跳都写成相对自己所在目录的名字);
- §9.3 确定性深度优先遍历(第一个失败按固定顺序报告)。

## 为什么除深度外一切都远未触碰(单缺陷的证明)

| 预算项 | 上限 | 本用例实际 | 结论 |
|---|---:|---:|---|
| 引用深度 | 64 | **65** | **越界** |
| 唯一渲染节点数 | 4,096 | 66 | 远低 |
| 唯一实际源文件数 | 8,192 | 66 | 远低 |
| 累计 PXL 字节 | 64 MiB | 约 6 KiB | 远低 |
| 累计 PNG 像素 | 2^24 | 0(无 PNG) | 0 |
| 全局光栅工作 | 2^24 | 66(每文档 1 次写入) | 远低 |

每个文档自身也都合法:画布 1×1、单图层、单 op、光栅工作 1。**唯一**被违反的就是深度。

## 为什么是 65 层而不是 64 层

上限写的是“最大深度 64”,即**恰好 64 层是合法的**。用例必须越界才算负例,所以链长取 65。
边界“恰好 64 合法”那一侧需要一个正例才能双向钉住,但它的期望像素要等阶段 2 的 resolver
落地 —— 见下方待确认项。

## 判定方式

实现必须以 `PXL011` 失败,且不产出任何输出文件。`expected.error` 只写码。

## 待规范确认

1. **“恰好等于上限”的正例**:深度 64、全局光栅恰好 2^24 这类边界,按 §10.2“任一先达到上限都报
   `PXL011`”一句里“达到”与“超过”的口径,究竟“等于”是合法还是越界?本负例只用**严格越界**的
   65 / 20,971,520,所以不受该歧义影响;但写正例前必须先裁定,否则正例可能永远失败。
2. 本条用 66 个文件表达,是“一个用例一个目录”下表达深度的唯一办法;若规范希望给定一个
   生成器配方(§13 目前无生成型用例概念),请指定。

## 与 v0 的差异

v0 无外部引用,不存在引用深度;v0 的 `PXL011` 不存在(那是 v1 新增码)。
