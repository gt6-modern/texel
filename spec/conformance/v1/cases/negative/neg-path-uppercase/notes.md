# v1/cases/negative/neg-path-uppercase

- 形态:`negative` 负例(PXL.md §13.3);`defect: path`
- **受测侧**:阶段 R1(§11.2 第 11 行:逻辑路径语法)
- 受测输入:`entry.pxl`
- 期望错误码:`PXL008`(见 `expected.error`,一行 + LF)
- 缺陷数量:**1**(声明的 `path` 含大写字母)

## 覆盖条款

- §7:逻辑路径只允许 ASCII 小写字母、数字、`-`、`_`、`.`、`/`;大小写敏感,
  **大写字母一律非法,不自动转小写**;
- §14 保留与延期:Unicode 或大写逻辑路径、Windows 反斜杠一律按 §7 拒绝(`PXL008`);
- §11.2 阶段 R1。

## 缺陷(只有这一处)

`assets.blade.path = "parts/Blade.pxl"`;`B` 是大写。

**目录里确实存在 `parts/Blade.pxl`,拼写逐字符相同。** 这个设计是关键:于是“它为什么失败”
不可能是“文件不存在”(`PXL009`),也不可能是“拼写不符”(`PXL008` 的 `CASE_MISMATCH` 分支,
那需要 `spelling.tsv`,见 `neg-path-case-mismatch`)。唯一解释是**声明路径本身语法非法**。

反过来说:一个**跳过 R1 语法检查直接去解析**的实现会命中 `parts/Blade.pxl` 并**渲染成功**,
本条因此失败 —— 这正是它要抓的错。PRD §9.1 明写“大写字符一律非法,而不是自动转小写”,
而“自动转小写”与“干脆不校验”在像素上都表现为通过。

## 判定方式

实现必须以 `PXL008` 失败,且不产出任何输出文件。

## 待规范确认

1. 同一条 §7 也拒绝**反斜杠**(另一类“像路径但不是逻辑路径”的写法)。按“一个负例目录只放一个
   缺陷”的既有纪律(§13.3.6 / v0 §13.1),本条只放大写。是否需要独立的 `neg-path-backslash`,
   请规范指定 —— 本阶段不自行添加。

## 与 v0 的差异

v0 无逻辑路径,本条是 v1 独有语义。被引用的 `parts/Blade.pxl` 正文本身是合法 v1 文档,
差异仅在于它被一个非法路径引用。
